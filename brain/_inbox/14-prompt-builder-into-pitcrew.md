# Folding the prompt builder into Pit Crew

**Status, 11 Aug 2026: requested, not built.** Handed to the Claude Code session as
`HANDOFF-prompt-builder-into-pitcrew.md` in the app repo, with the artifact's source
checked in alongside it as `reference/gt7-race-engineering.html`.

Kept here for the same reason as `12` and `13`: so this knowledge base knows what the
app has been asked to become, and can tell a request apart from a fact.

---

## The decision

The **GT7 Race Engineering** HTML artifact is being **retired**. Its three tabs move
into Pit Crew, which becomes the single source of truth for everything the programme
knows about a car, a circuit and a session.

Rationale: the two tools held the same information twice and it had begun to drift.
Slider ranges existed in the app's `rangeRecord` *and* in a hand-edited `RANGELIB`
object literal in the HTML *and* in `11-car-slider-ranges.md`. The setup as run
existed as real app state and was re-typed into a free-text box. Car, circuit, event
format, multipliers, compounds, assists, laps, pace and fuel were all already in the
database and all re-entered by hand.

**The rule the port is built on:** if the app already knows it, the app fills it in.
The driver is only ever asked for what the app cannot know — symptoms, the biggest
limitation, balance drift, tyre state at the end, priority this round, and notes.
Facts from the app; perception from the driver.

## What the app will produce

Three prompts, each prefilled from app state, each copied to the clipboard and pasted
into a project session here. **No model API calls from the app** — it assembles
context, the reasoning stays in this knowledge base.

| | Prompt | When | Returns |
|---|---|---|---|
| **A** | Setup Brief | Before a new combination is run | Race + quali sheets, gearing derivation, strategy note, three things to test |
| **B** | Setup Refinement | After practice / quali / TT | Diagnosis, revised sheets, delta table, what to feel for |
| **C** | Event Outcome | After a completed race | Post-mortem, revised sheets, strategy review, **and knowledge-base updates** |

A and B are ports of `buildBrief()` and `buildLog()`, wording preserved — the prompt
text is tuned for this knowledge base and is not to be "improved" during the port.
Two additions: prompt A's `## Context` is populated from real session history rather
than a free-text box, and both A and C carry `refuelRateLps` and `pitLossSecs` with
provenance tags.

**Prompt C is new.** Today the post-race case is a variant branch that under-uses what
the app knows by the end of a race. It adds planned-vs-actual strategy with every
assumption's provenance, `callsMade` **including declined calls**, the `wear` section
with its sources, and gearing (`matchesSheet`, `gearingConstantK`, `shiftsInCorner`)
once the 1.2 export exists.

Its `What I need back` asks for knowledge-base updates **stated separately and
explicitly**: what to record about this car, this circuit and this combination; what
should be measured next session; and — the item that never appears unless it is asked
for — **any claim in this knowledge base that the event contradicts**. Every item
carries a confidence flag: measured, or inferred and awaiting a second event.

That is the continuous-learning leg, and it is the reason prompt C exists.

## The return leg

- Setup sheets keep coming back with the `gt7-pitcrew/1.1` paste blocks from
  `09-setup-sheet-format.md`, race block first, one block per sheet. The Event
  screen's parser is unchanged; *"22 of 23 settings, 6 gears"* remains the
  acceptance string.
- The app gains somewhere to **store the reply** against the session that produced it,
  and **logs every prompt issued** with a template version. Same reasoning as
  `callsMade`: advice that is never recorded cannot be audited.
- Prompt templates are versioned data, not code. A returned sheet is traceable to the
  template that asked for it.

## What this changes here, once it lands

Five documents currently describe the HTML tool as the front end and will need
rewriting when the work is delivered. **They are not to be edited from the app repo.**

- `00-INDEX.md` — the **Tooling** section describes the artifact's three tabs and
  names the register as the persistence layer for slider ranges. Both change: the app
  becomes the front end, and its range store becomes the primary record, with this
  register as the human-readable copy.
- `09-setup-sheet-format.md` — the paste-block section stands unchanged, but the
  framing shifts from "paste into the tool" to "generated by the app".
- `10-pit-crew-data-format.md` — the note that Leon pastes the payload into the
  Driver Feedback tab becomes: the app embeds its own payload in prompt B and C.
- `11-car-slider-ranges.md` — **"How a car gets added"** step 2 points at the tool.
  It becomes the app's car screen, and the hand-edit of `RANGELIB` disappears entirely.
- `12-pitcrew-app-brief.md` — §1 job 3 describes exporting *for* an external HTML
  tool. That tool is gone; the app wraps its own payload.

## Constraints carried into the port

- **The app composes prompts. It never gives setup advice.** No tuning heuristics, no
  suggested values. If a rule about camber appears in the app, it is in the wrong place.
- **Never fabricate to fill a template.** Absent data is omitted or explicitly labelled
  not measured. A zero that means "not measured" gets diagnosed as a real value.
- **`wearMeasuredAtRaceMultiplier: false` must reach the prompt.** Multiplier
  linearity is still assumed, never demonstrated.
- **No `tow` field, ever.** GT7's feed has no proximity or closing speed; whether a top
  speed was set in a tow comes from the driver in notes.
- Values with a per-car range are emitted as percent of range **plus** clicks **plus**
  absolute, marked verified or estimated.

## Acceptance — the artifact is deleted only when

1. **Zero re-entry** — prompt B for a recorded session requires only the perception
   fields; everything else is drawn from stored state.
2. **Range single-source** — measure a car once on the car screen and all three
   prompts and the export carry it, marked verified, with no other file edited.
3. **Round trip** — prompt C → sheets → paste block → *"22 of 23 settings, 6 gears"*.
4. **Honest gaps** — all three prompts remain usable with no telemetry, no strategy and
   unverified ranges, with every absence labelled and no defaulted zeros.
5. **No advice** — no tuning language anywhere in the new screens or templates.
6. **Reproducible** — same session and template version generates byte-identical output
   apart from the timestamp.
